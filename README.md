# MotionStage

**拉片、片内人物检索、Three.js 白模还原。**

首页选择视频即按文件名建立项目并导入。项目内以「拉片 / 人物 / 三维还原」三个并列工作区呈现结果，共用当前镜头与播放位置；不需要逐项确认后才能切换。MotionStage 面向构图、人物出场、角色走位、摄影机和动作衔接的核对，使用内置舞台与彩色简化代理表达近似还原。

默认界面优先展示影片、人物卡和三维对照；人工修正、任务详情、角色与相机调整、模型高级连接设置按需展开。产品名为 MotionStage，GitHub 仓库名仍为 NexArtMS。JWM 样片的场景工作台与流程演练入口已于 2026-09-29 移除（历史记录见 docs/progress.md）。

## 三个工作区

- **拉片**：原片、源帧关键帧、镜头列表与当前镜头摘要。需要修改时展开「修改本镜」或「调整本镜切点」，问题与修正说明也按需查看。
- **人物**：按姓名或已有描述筛选片内人物，点击人物卡查看出场镜头，再从出场跳到对应位置的拉片或三维。默认只展示人物，动物单独查看与统计；不提供外部人物库或未知演员身份识别。
- **三维还原**：以整片原视频与 Three.js 白模对照播放为主，支持镜头视角、自由观察和俯视。角色、相机调整及资产导出收在各自入口；缺动作时如实显示占位。

三个入口始终并列，切换保留当前活动镜头与播放位置；拉片候选切点在采用前保持独立。旧项目不会因界面升级自动重跑。拉片引擎与早期验收见[接入计划](plans/shot-analysis-integration-plan.md)、[实际验证记录](docs/reports/shot-analysis-acceptance/README.md)。

逐镜语义需要明确配置视觉模型，见[配置与协议](docs/shot-analysis-provider.md)。首页或项目页的「模型设置」支持添加供应商、填写多个模型、测试图片输入和选择默认视觉模型。未配置或密钥未保存时自动降级为「语义待配置 · 底稿已保留」：切镜、关键帧与拉片报告照常生成，后续检测与动作不受影响，不会伪造景别、动作或人物数量；配置后点「更新 / 重试拉片」只补跑缺失镜头。已固定引入 reelbench 词表、校验器与 Markdown 报告模块；模型结果保留证据和人工覆盖，切点修正保存为候选版本后采用。

**请求效率（联系表看片）**：逐镜语义的图像输入采用上游 video-shots 同款联系表——ffmpeg 把每批采样帧拼成一张 3×4 网格大图，每格左上角标注 `shot f帧号`，单请求图片数从约 28 张降到 2~3 张；组图失败自动回退逐帧。针对推理型视觉模型（如 MiniMax-M 系列，深度思考不可关闭）的实测调参：默认一批 6 镜、单请求超时 240 秒，可用 `STUDIO_SHOT_ANALYSIS_BATCH_SIZE`、`STUDIO_SHOT_ANALYSIS_TIMEOUT_MS` 覆盖。跨运行续种按服务身份（provider/model/endpoint/protocol）判定，调参变化不会作废已完成的镜头。

会话中由助手查看证据后导入的结果单独标记来源，不代表已配置后台 API；当前 57 镜头实例见[本次会话视觉分析记录](docs/reports/session-visual-analysis/README.md)。

### 视觉模型设置

默认显示所选模型、密钥是否已保存，以及「设为默认视觉模型」。已有可用配置的编辑表单默认收起，新增配置或缺少已保存密钥时展开；基础表单只要求模型 ID 与按服务需要填写的密钥，地址、协议和供应商名称放在高级连接设置，自定义服务会展开需要填写的连接项。新增供应商不会自动替换当前默认模型。

**「连接诊断」按需展开，「测试连接」不是使用前提。** 选中默认视觉模型后可直接开始拉片，不需要先通过测试。诊断区区分请求失败与图片判分未通过，并保留模型实际返回内容；诊断未通过不强制阻止选择默认模型，实际分析仍需接口可正常调用。未保存修改在关闭或切换供应商时会提示，地址更换到不同请求目标时保留重新填写密钥的保护。

判分要求模型严格返回英文小写色名的纯 JSON。已加入解析容错，可接受 `<think>` 思考段、Markdown 围栏和前后说明文字；仍不合规时会在界面上列出具体不符项。

**API Key 的存放位置**：Windows 用 DPAPI 加密后持久化；**macOS／Linux 只保存在服务进程内存中，重启服务后需要重新填写**（这是平台的默认取舍，不是缺陷）。若希望长期免重填，用环境变量配置：

```sh
export STUDIO_SHOT_ANALYSIS_PROVIDER=minimax
export STUDIO_SHOT_ANALYSIS_MODEL=MiniMax-M3
export STUDIO_SHOT_ANALYSIS_ENDPOINT=https://api.minimaxi.com/v1
export STUDIO_SHOT_ANALYSIS_PROTOCOL=openai-chat-completions
export STUDIO_SHOT_ANALYSIS_API_KEY=sk-...
npm run serve
```

国内与国际是两套独立密钥、不能混用：国内 `api.minimaxi.com`／`api.minimax.cn`，国际 `api.minimax.io`／`api.minimax.chat`。密钥与区域不匹配会得到 HTTP 401。

排查连接问题时可直接运行诊断脚本，它复用项目内同一份测试图和请求体，输出与界面完全一致：

```sh
MINIMAX_API_KEY=你的key MINIMAX_BASE_URL=https://api.minimaxi.com/v1 \
MINIMAX_MODEL=MiniMax-M3 node app/diagnose-minimax-vision.mjs
```

### 片内人物与按需修正

人物页默认展示筛选、代表图、名称、已有描述和出场镜头数，自动匹配标为暂定。填写已知人数不是使用前提；无需先理解代理分组就能查看出场。

- 在所选人物的局部修正中，可以改名、核对、忽略或拆出归属错误的出场。
- 展开「修正人物」后，可批量合并、调整用于三维的角色，或核对尚未归属的出场。相似结果只提示「外观接近，待核对」，不把颜色相似分数显示为身份概率。
- 人数或结果不对时，再展开人数提示与重新整理。**重新整理仅归组已有出场**；切点采用后或漏检时，可另选「重新检测人物出场」，成功后继续已有的检测 → 人物整理 → 动作 → 相机链。动物在单独类别中按需检测；动物代理与动作还原仍未实现。
- 检测需要已导入视频、镜头、可用检测模型，并等待当前任务结束。已有人工决定受保护，重新检测或整理可能被拒绝；界面会显示原因，不会承诺覆盖人工结果。

代理分组继续保留在修正和三维调整工具中，例如将不同素材人物指定为同一个成片角色，共享 GLB 外观并保留各段动作。正式确认用于可选的版本冻结，**不是查看拉片、检索人物、三维预览或导出已有资产的前提**。

人物汇总会使用拉片语义主体信息或外观颜色线索，仍属于待核对建议，不能保证跨镜身份准确；人数提示也不能保证每镜归属正确。完整三维代理视频渲染仍待实现。

## 快速开始

需要 **Node.js 22.12 或以上版本**、npm，以及可在命令行调用的 **FFmpeg / ffprobe**；本项目在 Node.js 22.22.3 上验证。浏览器需要支持 WebGL。界面为响应式布局，桌面与窄屏/移动端宽度均可使用。

FFmpeg 需 **5.0 或以上**（本项目使用 `-fps_mode` 而非已废弃的 `-vsync`，在 FFmpeg 9.0.2 上验证）。若 `GET /api/studio/capabilities` 返回 `"ffmpeg": false`，说明启动服务的终端找不到 FFmpeg——确认它与 `node` 在同一条 PATH 中，或设置 `FFMPEG`／`FFPROBE` 环境变量。

```sh
git clone https://github.com/yaopengcheng11/NexArtMS.git
cd NexArtMS/app
npm ci
npm run build
npm run serve
```

打开 <http://127.0.0.1:8199/>。服务仅监听本机，终端关闭后服务停止。

| 页面 | 地址 | 用途 |
|---|---|---|
| 混剪项目（主页） | <http://127.0.0.1:8199/> | 导入视频即建立项目，进入拉片、人物、三维还原三个工作区 |
| 刚性角色试验 | <http://127.0.0.1:8199/?lab=rig> | 查看 CL0／CL1／CL2、合成姿态及 GLB 导出 |

仓库不携带任何样片或预置项目；首次使用从主页「导入视频」选择自己的视频即可建立项目并启动自动处理，项目名称可在设置中修改。

混剪项目工作台需要本机安装 **FFmpeg**（在 PATH 中，或设置 `FFMPEG`/`FFPROBE` 环境变量）。上传自己的视频时，首版输入范围为：MP4/MOV、H.264/H.265、最长 120 秒、最高 1080p；可用 `STUDIO_MAX_UPLOAD_MB`、`STUDIO_MAX_DURATION_S`、`STUDIO_MAX_WIDTH_PX`、`STUDIO_MAX_HEIGHT_PX` 调整。超出范围会得到明确原因与预处理建议。

### 启用自动人物检测

```sh
node app/scripts/fetch-detector-model.mjs
```

下载完成后重启 `npm run serve`。权重保存在 `data/models/`，使用随 npm 安装的可选依赖 `onnxruntime-node` 在本机推理；权重未随仓库分发。模型来源、哈希与许可记录见[模型决策](docs/model-decisions.md)。未安装或无法加载模型时，人物检测任务会明确失败；人工补标仍可使用。

## 混剪项目工作台

用户流程是：**导入视频 → 在拉片 / 人物 / 三维还原中查看结果 → 按需修正**。预览生成、源帧 PTS、切镜、取证、逐镜语义与报告在后台处理；拉片收尾后自动续跑人物/动物检测 → 全片角色汇总 → 连续动作初稿 → 人物尺度运镜估计。语义不可用（未配置模型、缺密钥、鉴权失败或分析失败）会显示原因并保留可用底稿；处理记录、进度与重试按需展开。动物代理与动作还原仍待实现，项目使用内置场景。

### 集中修正该改什么

拉片默认展示观看与定位所需的结果，编辑表单、切点工具和修正说明按需展开：

1. **切点**：展开「调整本镜切点」拆分、移切点或合并，再「采用此候选版本」。采用会重写活动镜头表，使受影响的人物检测、相机与动作过期；随后可在人物页的修正工具中重新检测并续跑现有还原链，人工决定的保护仍生效。
2. **本镜人物出场**：不参与计算，作为手工归并角色时的参考。
3. **景别／镜头类别／运镜**：下拉选择，快速扫一遍。
4. **报告补充（可选）**：画面描述、动作、构图、场景、节奏、不确定项，收在折叠区，**只写进拉片报告**。

每镜改完点「保存本镜修正」。「查看分析中的不确定内容」只汇总系统判定的问题（字段缺失、校验未过），**模型给出但实际错误的结果不一定出现在其中**，仍需结合原片核对。

- **三维整片对照**：三维还原工作区将原片与白模同步呈现，可切换镜头视角、自由观察和俯视，并沿时间轴定位。内置舞台提供地面与尺度参照，有动作产物时播放相应动作，缺失时显示占位；人物位置与相机仍是单目近似估计。身高、CL0／CL1／CL2 外观、版本冻结与高级相机校准收在「调整角色与相机」中。

- **多项目与媒体（M1）**：每个项目有独立目录 `data/projects/<id>/{media,proxies,observations,previews,exports}`；原片只读保存并记录 SHA-256；ffprobe 探测时长、尺寸、旋转与帧率；逐呈现帧生成 PTS 时间戳映射（可变帧率按实际时间戳，不按固定帧率推算）；后台任务依次生成可播放代理、PTS 映射与自动切镜，任务支持进度、取消、重试，服务重启后中断任务如实标记失败。元数据存于 `data/studio.sqlite3`（SQLite WAL）。
- **切镜与出场候选（M2）**：自动切镜基于相邻呈现帧直方图距离（JWM 替身集召回 100%、精确率 83.6%，见 `docs/reports/baseline-mixed-cut.json`）；单帧闪白抑制；人工改切点要求覆盖全部帧且无缝。人物检测/姿态用 YOLOv8n-pose（ONNX）：运行 `node app/scripts/fetch-detector-model.mjs` 下载权重（AGPL，见 [模型决策](docs/model-decisions.md)）并重启服务；未配置时 detect 任务如实失败。自动链检测人物与动物，人物页修正工具可按当前类别重新检测。动物由可选第二模型 YOLOS-tiny（COCO-91，Apache-2.0，`app/scripts/fetch-detector-model.mjs` 一并下载）负责，动物候选不参与人物归组与确认门槛。检测逐帧框经镜内 IoU 跟踪成为出场候选（约 10fps 采样 + COCO-17 关键点观测）；展开「修正当前镜头的出场」可人工补标、拆分、连接、删除误检。跨切镜轨迹绝不自动连接。
- **相机与动作（M4/M5）**：有 ≥6 个米制三维地标时逐镜 PnP 求解相机（纯 JS DLT+高斯牛顿，A5 门槛：中位重投影 ≤8px 为高置信）；证据不足只能人物框粗估并强制"待人工确认"。动作把二维姿态提升为固定骨长三维关节（骨长偏差由构造 ≤0.1%，A6），输出 y 向上、地面为 0 的角色局部坐标系动作与接触标注；单目深度歧义不消除，需人工逐镜审查。
- **交付（M6）**：一键导出交付包——manifest（含输入哈希与算法版本）、镜头时间表、角色与归并清单、相机轨迹、逐实例动作 JSON、每组一个共享 GLB 代理资产（包含组内各段有效出场动画）。预览视频渲染、可见场景资产（M4S）与 DCC 回读实测不在首版范围，manifest 中如实标注。
- **角色归并与确认（M3）**：自动建立临时角色供初稿使用；人物页展开「修正人物」后可批量归组或忽略，三维页展开「角色外观与身高」可修改或创建角色资产。不同人物同组时共享代理外观，同镜冲突仍保留检查。「保存已核对版本（可选）」中的正式确认要求先处理候选与冲突，并冻结媒体、切点、候选和归并版本；上游修改会使冻结失效，但普通预览与导出不要求先正式确认。
- **项目设置和删除**：项目设置可修改名称与说明，「三维场景设置」按需展开。当前使用「内置舞台 · 近似还原」；从视频生成真实场景尚未实现，选项禁用，旧项目可以改回内置舞台。删除须输入完整项目名，并等待上传、任务和文件读取结束；删除采用回收站模式（先移入 `data/.deleted-projects/` 再清理），文件被占用时自动重试并如实报错。数据库当前版本为 v9，已有数据库升级前自动生成备份；新增拉片记录也纳入项目删除范围。
- **旧项目的人物汇总**：人物页可直接查看已有出场；需要调整时展开「修正人物 → 人数或结果不对？」再填写可选人数并重新整理。已核对或已分组的人工决定受保护，必要时会拒绝重新整理而提示修正具体出场。颜色线索与语义建议均不能证明真实身份。
- **数据隔离**：混剪项目使用独立的数据库与项目目录；删除项目不影响其他项目。

写入语义与正式流程一致：所有修改携带 `baseRevision`，过期写入返回 409；未处理候选阻止正式确认并返回 422。API 一览见 [开发计划 §4](plans/development-plan-mixed-cut.md)。实机验收（导入 JWM 原片 → 切镜 → 真实检测 → 归并确认 → 动作 → 交付包）可用 `BASE_URL=http://127.0.0.1:8199 node app/scripts/acceptance-mixed-cut.mjs` 复跑，报告见 `docs/reports/acceptance-mixed-cut.json`；浏览器冒烟用 `node app/scripts/browser-studio-probe.mjs`。

需要使用其他端口时，例如 macOS／Linux：

```sh
PORT=8200 npm run serve
```

不要直接双击 `index.html`；数据保存、视频读取和页面资源需要通过本地服务访问。

## 代理外观档位

### CL0／CL1／CL2 三档小人

| 档位 | 可见部件 | 表达内容 |
|---|---:|---|
| CL0 | 2 | 头与整体躯干，用于轮廓、重心和大动作沟通 |
| CL1 | 6 | 加入整段四肢，用于行走、转身和基础姿态 |
| CL2 | 27 | 分段四肢、关节和手脚，用于打斗及接触检查 |

代理角色组按档位共享同一资产：部件随骨骼刚性运动，切换档位保留根位置和姿态；CL1 保持整段肢体长度；导出使用单骨 100% 权重，无需人工刷混合权重。在三维还原的「调整角色与相机 → 角色外观与身高」中按组切换档位。

### 数据与版本

混剪项目的元数据保存在 `data/studio.sqlite3`，上传的视频与产物保存在 `data/projects/<projectId>/`。前端保存时携带基准版本；上游变更会使既有确认失效。

仓库不携带任何用户项目、模型权重或完成记录。新克隆从主页「导入视频」开始。备份本地工作时需同时保留 `data/`（混剪项目数据库与媒体）。

SQLite 当前 schema 为 **v9**（含拉片运行、身份层 subject/species、代理级别与运镜轨迹）；已有数据库升级前生成 `data/studio-before-v<版本>-<时间戳>.sqlite3`。项目人数提示、角色代理组和人工决定会持久保存，未归属出场在重启后仍保持待核对。数据库备份不包含媒体文件；项目删除会清理当前项目的数据库记录及项目目录（含拉片记录），历史数据库备份需自行管理。

## 开发与验证

### 本地开发

先在一个终端启动默认端口 8199 的服务：

```sh
cd app
npm ci
npm run serve
```

再在另一个终端启动前端：

```sh
npm run dev
```

打开 <http://127.0.0.1:8198/>。前端的数据接口代理指向 8199；开发时保持后端使用默认端口。

### 自动检查

```sh
npm run check
npm run build
```

自动检查覆盖骨架、同步播放、切镜、跟踪、媒体管线、SQLite 迁移与版本冲突、角色确认与失效、相机求解、近似动作、HTTP 导出与 GLB 回读、项目设置和删除，以及拉片引擎（证据帧、联系表、逐镜语义校验、blocked 降级、缺密钥续跑、视觉供应商配置与密钥）。人物相关回归包含已知人数整理、未归属出场保留、人工决定保护、代理组继承和旧动作引用失效；本轮具体结果见[三工作区验收记录](docs/reports/three-workspaces-acceptance.md)。自动测试使用合成数据与可丢弃项目，不等同于真实混剪的识别精度验收。

**macOS 上有 3 项固定失败**（`scripts/studio-project-deletion.test.mjs`），属测试用例的平台差异，不是功能缺陷：实现侧 `project-operations.mjs` 用 `fs.realpathSync` 解析项目目录做防符号链接检查，macOS 的 `/var` 是 `/private/var` 的别名，导致路径与测试中 `os.tmpdir()` 返回值字符串不相等，测试注入的 `fs.renameSync` 桩不会触发。实现行为正确，应修测试侧而非放宽 realpath 检查。

### 浏览器检查（可选）

```sh
npx playwright install chromium
node app/scripts/browser-studio-v3.mjs
```

旧版角色卡片浏览器检查自行启动临时服务、创建临时项目并清理数据，需先运行 `npm run build`；历史报告 `docs/reports/studio-role-cards-browser.json` 记录两张角色卡、分组、持久化、390px 窄屏、设置和删除。旧脚本可能仍使用原界面的文案与结构，本轮三工作区的浏览器结果以[当前验收记录](docs/reports/three-workspaces-acceptance.md)为准。

其他浏览器脚本可通过 `BASE_URL` 指向运行中的服务，部分脚本支持 `CHROME_PATH` 或 `PLAYWRIGHT_MODULE`；具体参数见各脚本。报告写入 `docs/reports/`。

- `browser-studio-probe.mjs`：混剪项目列表与工作台渲染检查（只读，不修改项目数据）。
- `browser-studio-v3.mjs`：角色卡片、分组、项目设置与删除（独立临时项目）。

历史实测记录（含 JWM 样片演练的存档验证）见 [执行进度](docs/progress.md) 与 [验证说明](docs/reports/README.md)。
