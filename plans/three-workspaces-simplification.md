# MotionStage 三功能简化实施计划

日期：2026-09-30。范围：现有 React / Three.js 工作台，用户已授权计划完成后直接实施。

## 完成条件

用户只需围绕三个任务工作：拉片、检索人物、三维还原。三者有始终可见的并列入口，共用当前镜头和播放位置。无需理解检测、轨迹、代理组、PnP、版本冻结等内部概念，就能查看现有分析结果、找到人物出场、播放三维初稿。

本轮保留现有算法、数据库和人工修正，不新增外部身份库，不将近似白模表述为精确场景复原，也不将尚未实现的 MP4 渲染列为可用导出。

## 审视依据

- 实际运行页：当前 50.13 秒、57 镜项目；1280×720 窗口下，默认页面约 3,788px，展开后续工作台约 8,454px，整片播放标题约在 7,622px。
- `app/src/studio.tsx`：拉片之后依次叠放任务、切镜、人物、相机、代理确认、静态三维、同步播放、交付；把后台模块当成了用户步骤。
- `app/src/StudioShotAnalysis.tsx`：说明、切点修正、问题列表默认展开，观看与编辑混在一起；正文修改需逐镜保存。
- `app/src/StudioPeople.tsx`：已经支持点人物看全部出场，但没有名称/描述筛选；人物检索混入代理分组和动物。
- `app/studio/router.mjs`：首页人物数包含动物。外观相似百分数也容易被误认成身份概率。
- `app/studio/jobs.mjs`：自动链已存在；生成动作和现有导出并不要求先正式确认角色。旧阶段文案与真实能力不符。
- 拉片与三维当前分别管理视频时间；候选切点必须与活动镜头上下文隔离。

## 目标界面

```text
项目名称                         处理状态  ·  设置 / 更多
             拉片       人物       三维还原
--------------------------------------------------------
拉片：       原片与关键帧       镜头列表 / 当前镜头摘要
人物：       人物筛选与卡片     所选人物的出场 → 定位播放
三维还原：   原片 / Three.js 对照播放器，镜头时间轴
--------------------------------------------------------
当前镜头 / 播放位置             仅在需要时展开修正
```

“导入视频”直接使用文件名建立项目，项目命名不再是首次操作的前置表单。已有项目仍可改名。

## 渐进披露规则

| 情境 | 默认显示 | 用户操作后才显示 |
|---|---|---|
| 拉片 | 原片、关键帧、镜头表、当前结果 | 修改本镜 → 景别、运镜、文字；调整切点 → 拆分/移动/合并 |
| 找人 | 名称/描述筛选、人物卡、出场镜头 | 核对出场 → 改归属/拆开/忽略；结果不对 → 已知人数与重新整理 |
| 三维 | 对照播放、近似/占位状态、更新与导出入口 | 调整 → 相机/角色；高级 → 地标、代理等级、版本冻结 |
| 模型未配置 | 受影响区域显示“补充自动分析”入口，保留可用底稿 | 配置服务/模型/密钥；自定义地址、协议和连接诊断进一步展开 |
| 处理任务 | 一行当前处理状态或待处理提示 | 任务详情 → 进度、错误、重试、日志 |
| 有疑问的结果 | 当前结果上的“待核对” | 点开看具体证据；不把所有算法不确定项当成必须清空的任务 |
| 破坏性操作 | 收在项目设置中 | 删除或替换等动作发生时说明影响并明确确认 |

首次已配置的模型直接复用，不改变用户选定的模型或供应商。连接测试是诊断而非使用门槛。普通修正保留人工覆盖；切点采用继续明确提示下游影响，不能假称已支持一键撤销或全范围自动增量重算。

## 本轮实施顺序与边界

1. **页面重组**：用三个工作区取代阶段条和“后续工作台”。拉片和三维先呈现结果；把任务、相机、代理确认、历史等收进对应操作。移除 M4/M5/M6、PTS、算法编号等主路径文案。
2. **片内人物检索**：增加基于已有名称/描述的筛选；卡片进入出场，出场能跳回同一镜头的拉片/三维。默认人物，动物按需查看；修正人数口径和未校准百分比。匹配仍标记为暂定，不能承诺准确识别人脸或未知演员身份。
3. **共享上下文**：统一镜头与源时间位置，切换工作区继续当前位置；拉片候选版本的选中状态不污染活动镜头。保存未提交草稿，避免切页导致丢失。
4. **具体工具按需出现**：镜头结果的观看与修改分开；人物维护只在进入修正后显示；三维以整片播放为主，静态观察与技术调参作为次级工具；设置提供简洁配置与高级配置。
5. **导入及更新操作收敛**：选视频后创建项目并上传；保留服务端输入校验。三维“更新还原”负责提交现有动作/相机链，界面如实说明尚缺检测或其他前置产物的情况，不伪造已更新结果。
6. **验证和文档**：运行相关回归、完整现有检查与构建；用实际页面验证三个入口、筛选、镜头跳转、切页保留状态、展开/关闭工具及窄屏。真实素材仅只读浏览，不为验收重跑计费模型或覆盖已有人工数据。

不在本轮同时重做身份算法、合并数据库身份表、引入通用工作流引擎、改变任务并发或新增 MP4 渲染。后续真正的局部自动重算应沿候选切点的变化集合扩展 scope 与输入指纹；现有旧全量切镜入口从常用 UI 移除，避免误触全局失效。

## 验收清单

- 三个核心入口随时可见，彼此无“先全部确认再进入”的门槛。
- 首屏能看到当前功能的主要结果，不需要先读操作说明或滚过技术表单。
- 人物名/已有描述可筛选；搜索无结果有恢复入口；人物和动物数量分开。
- 当前镜头与时间可从人物出场进入拉片/三维，并在切页时保持；非零 PTS 与变帧率继续按源时间处理。
- 拉片编辑草稿不会因切页丢失；人工覆盖、版本校验和切点影响提示保留。
- 三维默认对照播放，缺动作和相机估计明确标注；只导出已实现的文件类型。
- 模型配置不强制测试连接，不静默替换现有模型；高级选项默认收起。
- 检查、构建和浏览器检查有实际结果；未验证的能力明确记录。
