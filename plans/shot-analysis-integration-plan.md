# 素材导入后的拉片阶段：接入与修改方案

状态：首阶段代码已实施，软件行为与真实素材底稿已验证；真实视觉模型的语义准确性尚未验收。日期：2026-09-27。实际证据见 [验收记录](../docs/reports/shot-analysis-acceptance/README.md)，模型配置见 [配置与协议](../docs/shot-analysis-provider.md)。下文保留目标与验收约束，未完成的真实语义检查不能视为已通过。

目标：用户上传素材后，自动完成全片镜头分析，生成可播放、可追溯、可修改的拉片表；识别不确定项集中到片尾统一修正。本次开发先完成这个阶段，后续人物/动物身份、叙事分组和三维还原继续使用其结果。

## 1. 现状与本轮改动范围

改造前上传入口在 `studio/router.mjs`，依次排队 `proxy / pts / cuts`；`studio/jobs.mjs` 在切镜完成后自动续接 `detect → people → motion`。本轮已改为前置成功才排下一阶段，自动运行至 `shot_report`。当前切镜器继续提供边界，新增引擎负责多帧证据和逐镜理解。

`studio/db.mjs` 的 `replaceShots()` 在写入切镜后就把项目从 `draft` 改为 `analyzed`。这个状态不能用来表示新拉片阶段完成。

保留现有上传、原片哈希、PTS、SQLite、任务进度、取消/重试及下游功能。新增拉片运行记录、镜头语义、证据和复核界面。新上传默认自动执行到拉片结果；旧项目不自动重跑、不改写既有分组和动作结果。

## 2. 接入 reelbench 的方式

采用 `video-shots` 的关键帧对照、词表、逐镜分析、补切/合并、质量检查和报告流程。已固定上游 commit `1b51af897b6a57556b85dfe96e0427e231b4b613`，在 `vendor/reelbench/video-shots/` 保留 Apache-2.0 许可证、逐文件 SHA-256 及适配说明。上游文件未修改；项目适配器实际调用其词表、校验器和 Markdown 渲染。

**首版保留现有切镜器作为主候选来源。** 当前样片此前实测为 57 个候选、参考的 46 个切点全部命中；上游 seed 默认生成 34 镜、漏掉 13 个参考切点。因此不应因为采用新 skill 就默认换掉现有切镜器。上游 seed 可以作为可选的对照检测器，记录算法与参数。

项目内部镜头以原片 `startFrame / endFrameExclusive / startUs / endUs` 为准。导出兼容上游的 seconds、start、end 仅作为交换或显示数据；禁止用已经保留两位小数的秒数反推并覆盖精确时间轴。

上游的 `cast` 是分析者维护的主体编号，不直接写成现有检测轨迹，也不直接创建叙事角色组。首版建立“视觉主体候选表”，人物与动物分开，保留不确定身份关系。

## 3. 自动任务链

建议运行级参数：`targetStage: 'shot_analysis'`、`analysisRunId`。前一阶段成功后再排下一阶段，避免前置失败后下游仍然执行。

```text
上传完成
  → proxy：可播放预览
  → pts：原片逐帧时间映射
  → cuts：全片切点候选及版本
  → shot_frames：每镜前段/中间/后段关键帧、联系表
  → shot_analyze：全片概览、分批逐镜语义、跨批主体候选核对
  → shot_validate：时间、引用、关键帧、语义格式、待修正项
  → shot_report：项目内拉片界面及可导出报告
  → 全片拉片初稿可查看，集中处理待修正项
```

- 不确定的景别、主体或运镜允许 `unknown`，必须附原因和证据位置；继续处理剩余镜头。
- 单批模型请求失败时有限重试，最终保留该批失败记录和未分析行，其余批次继续；结果明确标为存在缺失，不能冒充全片语义完成。
- 全部语义批次失败时结果为失败，不能因镜头表和图片存在就显示“拉片完成”。
- 原片/PTS 无效、模型未配置、鉴权不可用等运行前提不成立时，停止受影响阶段并展示具体原因。
- 取消后不再排队、不再提交迟到的模型结果。重试复用未失效的关键帧及已成功批次。
- 不自动续接本轮范围外的检测/动作任务；完成后保留下一阶段入口。这是当前开发阶段的边界，不是给每个不确定项新增人工审批。

任务执行沿用 `queued/running/done/failed/cancelled`；拉片结果独立使用 `not_started/processing/ready/ready_with_issues/blocked/failed/stale`。单镜再记录已分析、未知、失败或人工修改。前端展示已完成数、失败数与待修正数，避免只显示一个百分比。

## 4. 每镜数据与视觉模型接口

### 镜头记录

| 数据 | 内容 | 来源 |
|---|---|---|
| 时间与边界 | 原片帧号、PTS 微秒、持续时间、转场候选 | 程序测量与用户切点修正 |
| 关键帧 | 前段/中间/后段图像，精确帧号和 PTS；必要时加密 | 从当前原片版本抽取 |
| 语义 | 景别、类别、运镜标签、画面描述、动作、场景描述、可选节奏 | 视觉模型 / 用户 |
| 主体引用 | 人物候选 ID、动物候选 ID、物种（可未知） | 全片候选表 |
| 证据与不确定项 | 支持该判断的帧、原因、待核对字段 | 模型与规则检查 |
| 溯源 | 源片哈希、切镜版本、模型、提示词/schema 版本、运行 ID | 后台 |
| 修正 | 人工字段覆盖、修改时间、原始模型结果 | 用户编辑，独立保存 |

运镜先输出“固定/推拉/摇移/跟拍/无法判断”等描述；不把像素差分当相机轨迹。动作先描述可见事件和证据帧，不伪造骨骼动画或精确接触时间。

### 模型入口

当前代码只有 ONNX 人物/姿态/动物推理，未找到可生成逐镜语义的视觉语言模型调用。新增可替换接口，例如：

```ts
analyzeShotBatch({
  mediaHash, shotSetRevision, schemaVersion,
  shots, evidenceFrames, neighboringShots, subjectCatalog,
  signal
}): Promise<{ annotations, subjectSuggestions, issues, usage }>
```

- 先用全片联系表建立概览和临时主体表，再按小批次分析；每批携带主体参考图，避免每批重新编号。
- 模型仅返回允许修改的语义字段和切点建议；不允许它直接覆写机器时间字段。
- 关键帧不足以判断快速动作或切镜时，追加密集抽帧再判断，仍不确定则保留问题。
- 对疑似漏切/多切最多进行一轮密集证据复核；模型给出建议，由界面拆分/合并/移动生成候选，用户采用后切换活动边界。首版不自动改写切点。变化区间重新抽帧与分析，未变化区间按来源版本复用，不能沿用原段描述。
- 保存实际 provider/model/schema/prompt/参数，有限超时重试，不静默切换模型或供应商。来源版本变化时保留人工覆盖，重新生成机器语义；不能将旧模型输出标作新模型结果。
- 并发数、请求超时、每片调用预算和失败重试次数可配置，运行记录保存实际用量。
- 视觉模型/现有接口待用户选择；接口与存储设计不依赖某家供应商。安装 skill 本身不能替代后台模型执行入口。

## 5. 存储、版本与编辑保护

首版用两类新增记录即可，避免改写现有角色体系：

1. `shot_analysis_runs`：运行 ID、项目、媒体哈希、切镜版本、输入哈希、执行/结果状态、模型与 schema 版本、进度、结果/证据文件引用、问题统计。
2. `shot_annotations`：关联 run 与镜头边界版本，保存机器语义、人工覆盖及复核状态。全片主体候选表可先保存为运行目录内的带版本 JSON。

运行产物放在 `data/projects/<projectId>/analysis/<runId>/`，包含 manifest、镜头快照、主体候选、关键帧、批次输出、问题和报告。数据库保存索引及活动版本，文件以临时写入后原子替换提交。

原有 S01/S02 会在改切点后重新编号，不能单靠这个编号匹配旧标注。采用“媒体哈希 + 切镜版本 + 原片边界”标识归属，并保留显示镜号。

修改规则：

- 改描述、景别、动作文字：只保存字段覆盖，不调用 `replaceShots()`，不重做切镜。
- 重跑语义：写成新候选版本；保留人工修正，展示冲突或新建议。
- 拆分、合并、移动切点：创建新镜头版本；未变边界的人工语义可复用，变化的区间重新抽帧和分析。
- 改切点影响下游时：标记旧轨迹、相机、动作与导出为过期，不把旧结果静默挂到重新编号的镜头上；保存旧版本和用户分组，不批量删除人工决策。
- 运行中发生修改：提交前对比媒体/切镜/语义相关版本。过期任务不能覆盖当前结果，也不能删除新版本证据。
- 单次运行写入自己目录，不能清理共享的 `previews/shots` 目录来更新新报告。
- 已有轨迹与人工分组的旧项目：重分析先保存候选镜头版本及影响范围，用户采用后才切换活动版本；不在后台直接调用全量 `replaceShots()` 覆盖原结果。

## 6. 界面修改

增加“拉片”主视图，复用原片播放器：

- 上方显示真实进度：“候选切镜”“逐镜分析 18/47”“全片扫描完成，6 项待修正”。
- 原片播放时同步高亮镜头；点击镜头定位原片；支持逐帧查看与上一/下一镜。
- 镜头表展示首中尾关键帧、时间、景别、动作、运镜、人物/动物候选、问题标记。
- 侧栏显示所选镜头详情，允许编辑描述、调整切点、拆分和合并；保留模型原值。
- 待修正列表能直接定位镜头及字段，处理顺序不阻塞全片自动分析。
- 分别显示人物候选、动物候选和未确定数量；局部肢体、背身和固定水印不会仅因外观不同就被宣称为新身份。
- “切镜完成”“语义处理完成”“存在缺失/待修正”“用户已复核”分开展示。

暂不把已有 `project.phase === 'analyzed'` 解释成新阶段完成。使用独立 `shotAnalysis` 状态；旧项目保持原状态显示，选择“开始拉片”后才产生新运行。

## 8. 验收标准

1. 新项目导入后自动跑完全片，每个候选镜头都有一行状态；不确定项不要求中途人工确认。模型失败、跳过或尚未配置均清楚标明。
2. 所有镜头严格覆盖原片全部呈现帧，无空档、重复或越界；常帧率与可变帧率 fixture 均以原片 PTS 验证。
3. 当前 50.125 秒样片，修正后的切点与已有人工参考逐点比较，误差不超过 1 个源帧；不能靠硬编码“47 镜”或复制旧语义通过验收。初始候选的误检、漏检单独报告。
4. 当前样片能在视觉主体候选中持续引用 A/B 两个人；人物、动物分列，不把右下角水印列为已确认主体。无法确定的身份关系以候选与证据表达。
5. 每镜的前中后关键帧可解码且时间属于该镜；抽帧图、报告和视频定位一致。快动作需要更密集证据的镜头能补采。
6. 景别、动作、运镜等字段逐项保留证据或“不确定”说明。格式检查全过不等于视觉分析正确；短镜也不能因上游跳过运动检查就默认为正确。
7. 人工修正文案后重跑不丢失；改切点只重新分析受影响区间，旧 S 编号不会导致标注串镜；过期任务结果不能覆盖新修改。
8. 取消、单批失败、模型限流、重试及服务重启能保留已完成产物，状态如实；前置失败不触发下游任务。
9. 用 fixture 检查接口与恢复，再用用户确定的真实视觉模型跑完整样片；两类证据分开报告。真实模型未执行时不能称整阶段验收完成。
10. 增量迁移后旧项目可打开，已有人工分组与历史产物可追溯；本轮不自动重跑旧项目。

## 9. 实施顺序

1. 运行记录、schema、原片关键帧与新任务链；先让“拉片底稿”在项目内可查看。
2. 接入明确选定的视觉模型，完成全片概览、分批分析及问题记录；做到真实全片分析。
3. 镜头编辑、补切合并、人工覆盖保护和版本失效联动。
4. 当前样片完整验收，以及 VFR、取消、失败、重试、旧项目兼容检查。

供应商和模型仍是实施真实语义分析前需要确定的配置。其余首阶段已实施；验收第 3 条的自动修正准确性、第 4 条跨镜真实身份和第 9 条真实模型全片语义仍待后续配置后验证。相关初始切镜对照见 [reelbench 实跑报告](../docs/reports/reelbench-evaluation-2026-09-27/README.md)。
