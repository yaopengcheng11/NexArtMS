# MotionStage 自动混剪还原 V2：开发计划、框架建议与验收标准

> 版本：2.0 · 日期：2026-09-27。本文是后续开发与验收的工作依据，不表示所列能力已经实现或验收通过。
>
> 核心目标：用户上传混剪视频后，系统自动完成切镜、人物与动物检测及跨镜身份整理，在默认场景中生成覆盖全片时间轴的彩色代理三维初稿；用户最后集中修正身份、叙事分组、代理、动作、走位和相机。
>
> 文档优先级：本次已确认的用户要求优先于旧版“先确认角色、再生成动作”的流程。旧版 [开发计划](development-plan-mixed-cut.md) 和 [需求规格](mixed-cut-workflow.md) 保留为历史背景；本轮流程、动物范围和完成定义以本文为准。现有 JWM 演练继续独立保留。

## 1. 已确认目标、默认建议与范围

### 1.1 用户已经确认的产品要求

| 编号 | 要求 | 对开发的约束 |
| --- | --- | --- |
| R1 | 创建项目、上传混剪视频后自动切镜 | 不要求用户再次点击启动每一项分析任务 |
| R2 | 统计全片不同人物与不同动物，相同个体跨镜去重，人物和动物分开显示 | 镜内轨迹数、物种数、素材个体数不能混为一谈 |
| R3 | 用户可以把不同素材角色打成同一个叙事角色组 | 保留素材身份与出场来源；组内共享代理外观，各次出场仍保留自己的动作 |
| R4 | 用户选择 CL0、CL1、CL2 代理级别，不同角色使用不同颜色 | 配置需要持久化，且在三维预览与导出中一致 |
| R5 | 使用默认场景 | 默认舞台不依赖原片可见场景重建 |
| R6 | 尽量还原构图、动作、走位、运镜与剪辑节奏 | 完成标准是可连续播放的整段三维结果，不是静态截图或单独 GLB |
| R7 | 遇到不确定项时先自动生成全片，最后统一修正 | 质量问题进入待修正清单，不作为全片初稿生成前的人工关卡 |
| R8 | 动物也要打组、生成代理并还原动作 | 动物必须进入身份、分组、骨架、动作、播放和导出完整流程 |

### 1.2 本计划建议采用的默认设置

以下是为免去初稿前配置而提出的默认方案，并非用户已逐项指定的参数；应允许后续调整。

- 默认同时检测人物和动物；创建项目时不要求用户先知道角色数量。
- 每个自动素材身份先建立一个临时叙事组；不确定是否同一身份时保留独立候选，并记录疑似关联。
- 每组默认 CL1；用户可分别选择 CL0、CL1、CL2。CL 控制显示细节，不替代动作精度等级。
- 自动给新组分配可区分的稳定颜色，同时显示名称或编号；已有组的颜色不随列表排序改变。
- 使用内置中性舞台与统一尺度约定。舞台初稿采用版本化预设，避免引入复杂场景编辑器作为前置。
- 不自动推断“不同电影人物在叙事上应是同一个角色”。用户可以在初稿之后合组；也可在计算过程中提前配置下一版本。
- 人物组和动物组默认分开；不同骨架家族间的跨类合组暂不开放自动重定向。用户若需要这类创作能力，单独定义目标骨架与重定向规则。

### 1.3 第一阶段的输出边界

本轮重点是默认舞台中的可编辑代理还原，不要求复刻演员面貌、原片服装、材质、光照或可见场景。默认舞台仍应提供必要的地面和接触辅助体，以表达坐、站、落地等动作；辅助体不等于完整场景重建。

应交付：网页中的整段三维回放、与原片同步对照、统一修正入口、质量报告，以及建议纳入本轮的 MP4 预览与 GLB/JSON 资产包。MP4 编码参数和目标交付格式在里程碑 P3 实施前冻结，P9 执行实际回读；未验证的软件格式不写入已完成清单。

沿用现有输入起点：MP4/MOV、H.264/H.265、最长 120 秒。建议将画面上限定为旋转归一化后长边 1920、短边 1080，覆盖横屏与竖屏；这是对现有宽高限值的调整建议，须增加边界测试。VFR、无音轨、旋转元数据均进入验收。素材时长、同时可见个体数和硬件预算最终按 P0 基线冻结。

动物完整目标不缩减为“统计类别”。具体物种与动作支持范围尚未由用户逐项指定：先建立能力矩阵，再分批实现。首批建议猫、狗、马等常见四足类；鸟类及其他身体结构保留独立工作包。仅完成首批物种时，应称为相应支持范围的增量交付，不能宣称所有动物均已完成。

### 2.2 先修复的确定问题

| ID | 问题 | 修复要求 | 证据等级 |
| --- | --- | --- | --- |
| B1 | 单独重跑动物会替换已有自动人物；人物已有人工绑定时，动物检测反被整体阻止 | 检测结果替换、锁定与保护都按 subject 和输入版本限定范围 | 临时 SQLite fixture 已复现：有效人物 1→0；绑定后返回 409。未用真实模型重跑 |
| B2 | 动物拆分路径没有完整传递 subject；插入逻辑可能创建人物身份 | 所有拆分、合并、补标、改派保留类型与物种，不使用隐式人物默认值 | 代码审查发现，需补回归复现 |

| B5 | 只要生成至少一条动作，任务可能显示成功 | 技术执行成功与内容完整性分离，按全片/角色/镜头报告覆盖率 | 代码与历史报告确认 |

## 3. 产品流程与交互

### 3.1 自动初稿流程

```text
创建项目、上传原片
  → 校验媒体、生成时间映射与预览
  → 自动切镜
  → 人物 / 动物分别检测、跟踪、跨镜身份整理
  → 建立临时叙事组、默认代理、颜色和舞台
  → 按镜头求解相机、姿态、根运动与接触
  → 组装覆盖原片全时长的三维初稿及问题清单
  → 用户统一对照修正
  → 局部重算、更新预览与交付版本
```

从上传到初稿可播放，不依赖“正式确认角色映射”。保留旧确认记录作为历史人工决定；新流程把最终审查放在初稿后。用户也可以随时提前分组或改配置，但后台任务只能消费固定输入快照，不能在运行中混用前后两个版本。

空镜必须正常播放。某些镜头求解不足时仍保留时间和镜头结构，显示已标记的近似代理、缺失提示或无角色舞台；任何占位都不能计入有效动作覆盖率。模型缺失、文件损坏等技术失败必须明确显示，不能伪装成“画面没有人物/动物”。

### 3.2 页面结构

| 区域 | 主要内容 | 必须提供的操作 |
| --- | --- | --- |
| 项目概览 | 视频信息、整体进度、当前初稿版本、质量摘要 | 查看任务详情、取消、重试、切换历史版本 |
| 人物 / 动物 | 两个独立分区或页签；素材身份卡、代表帧、出场镜头 | 合并/拆开素材身份、补标、删误检、回看来源 |
| 叙事角色组 | 成片角色名称、组成员、CL、颜色、骨架家族、比例 | 合组、移出、改派、编辑配置 |
| 同步对照 | 原片与实时三维、全片时间轴、逐镜列表 | 播放、暂停、拖动、逐帧、倍速、并排/叠加 |
| 统一修正 | 身份、动物分类、动作、走位、相机、接触问题 | 点击问题定位区间、修改、重算、查看前后版本 |
| 导出 | 初稿或已审查版本、质量报告、格式与范围 | 导出预览/资产，查看未解决项与输入版本 |

卡片明确区分：检测出场数、暂定素材身份数、已核对身份数、叙事角色组数。未核对的数量显示“暂定”，避免把算法候选数作为确定结论。动物物种数量另列，不替代个体数量。

### 3.3 质量问题与修正策略

- 问题包含类型、时间区间、涉及角色/镜头、原因、证据与建议操作。
- 优先呈现大面积缺失、身份串换、明显构图偏差、脚滑/穿插、错误朝向及时间偏移。
- 用户可以暂时接受近似结果或明确忽略某个出场；接受记录不改变自动准确率，也不把缺失变为算法已求解。
- 修正要支持撤回。重分析结果先作为新候选版本，不覆盖用户锁定的身份、分组或关键帧。
- “允许同框”属于叙事表达设置。初稿中遇到同组同时出场，保留两个实例并提示冲突，不能删除一个实例或强迫用户先处理才能看全片。

## 4. 框架与模块建议

### 4.1 保留技术栈，逐步拆分职责

| 层 | 建议 | 具体边界 |
| --- | --- | --- |
| 前端 | 保留 React、TypeScript、Vite | 拆出身份管理、分组设置、播放器、问题面板，避免继续扩充单个 studio.tsx |
| 三维 | 保留 Three.js | 建立统一 RigFactory、时间采样器和镜头投影适配；预览与离线渲染共享 |
| API | 保留 Node.js 与现有路由 | 负责参数校验、版本、任务调度、产物发布；不在 HTTP 请求内执行长推理 |
| 数据 | 保留 SQLite 与项目目录 | 元数据/依赖/编辑记录入库；观测、模型、动画和视频作为带哈希的文件产物 |
| 媒体 | 保留 FFmpeg/ffprobe | 明确原片与代理的帧/时间映射，统一旋转与画幅处理 |
| 推理 | 保留现有 ONNX 适配器作为基线 | 先增加统一能力接口；仅在模型或性能需要时增加独立 Python worker |
| 重任务 | 子进程或受控 worker 池 | 按设备限制并发；计算结果交由主服务验证、事务提交 |
| 验证 | 保留 Node 测试、TypeScript 与浏览器验证 | 合成数据验证确定性，真实视频验证识别和还原质量，二者分别报告 |

本轮不要求整体迁移到新 Web 框架、微服务、Redis 或云平台。默认本机执行；增加远程分析应成为明确的产品选项与独立部署工作，不作为自动替代路径。

ONNX Runtime 提供 Node.js 绑定，可以承接现有推理接口；不同平台的执行后端能力有差异，不能把“已安装 onnxruntime-node”理解为“本机 GPU 已可用”。实现必须记录实际 provider，并用当前锁定版本验证。[官方 Node.js 说明](https://onnxruntime.ai/docs/get-started/with-javascript/node.html)

### 4.3 模型与算法适配接口

每个适配器至少声明：`name`、`version`、`weightsHash`、`subjects`、`species`、`skeletonSchema`、`inputTransform`、`executionProvider`、运行时与来源记录。

```ts
// 概念契约，不是可直接替换现有实现的代码。
interface AnalysisContext {
  projectId: string;
  runId: string;
  inputManifestHash: string;
  signal: AbortSignal;
}

interface ModelCapabilities {
  subjects: Array<'person' | 'animal'>;
  species: string[];
  skeletonSchemas: string[];
  supportsPartialPose: boolean;
}

// 所有实现返回结果引用、质量摘要和来源，不直接改项目当前版本。
// Detector.detect / Tracker.track / IdentityResolver.resolve
// PoseEstimator.estimate / CameraSolver.solve / MotionSolver.solve
// Retargeter.retarget / Renderer.render
```

更换模型只影响其适配器与被依赖产物，不能悄悄改变身份定义、骨架关节语义或时间基准。权重来源、使用条件、输出兼容性和效果都需在 P0/P4 记录；本计划不指定未经本项目实测的新默认权重。

| GET /api/studio/capabilities | 返回输入限制、模型/设备、物种/骨架能力矩阵 | 区分已安装、已加载与已验收支持，不只返回一个 detectorAvailable |

## 5. 数据模型与不变量

### 5.1 三层身份关系

```text
镜内出场 AppearanceTrack
  → 素材身份 SourceEntity（人物或动物个体，跨镜稳定）
  → 叙事角色组 NarrativeGroup（用户的成片表达）
  → 逐镜实例 ActorInstance（出场时间、动作与根运动各自独立）
```

同一人出现五镜：一个素材身份、五次或更多镜内出场。两部电影中的不同人物合组：仍保留两个素材身份，共享一个叙事组。两只同品种动物不能仅因物种相同而合并。

“素材身份”默认表示本片中被认为是同一个来源角色/动物个体，不是现实演员身份库；不根据演员姓名自动合并不同作品中的角色。证据不足时保留候选关系，用户决定最终归属。同一素材身份必要时可以对部分出场做叙事组覆盖，支持分饰多个成片角色。

### 5.2 实体与字段

| 实体 | 核心字段 | 不变量 |
| --- | --- | --- |
| Project | id、revision、schemaVersion、stagePreset、defaultProxyLevel、pipelineVersion | 默认配置与媒体分离，修改可追溯 |
| MediaSource | hash、originalRef、previewRef、ptsMapRef、previewTimeMapRef、rotationTransform、durationUs | 原片只读；原始 PTS 与归一化播放时间均可恢复 |
| Shot | id、revision、startUs、endUs、startFrame、endFrameExclusive、transition | 主时间线无缝；快切与渐变转场有明确语义 |
| AppearanceTrack | id、shotId、subjectType、species、intervals、observationsRef、revision、status | 同一轨迹不跨切点，不混入另一个个体 |
| SourceEntity | id、subjectType、species、name、representativeRefs、identityStatus、revision | 身份 ID 不依赖显示顺序；暂定与已核对区分 |
| IdentityMembership | trackId、entityId、confidence、source、locked、revision | 有效轨迹恰好归属一个当前身份，或显式 unresolved/ignored |
| NarrativeGroup | id、name、subjectType、color、proxyLevel、rigFamily、rigVersion、bodyScale、allowSimultaneous、revision | 颜色/CL/骨架持久化；组不改写原始身份 |
| CastingBinding | entityId 或 trackIdOverride、groupId、disposition、source、locked、revision | 优先级明确：人工出场覆盖 > 人工实体绑定 > 自动默认组 |
| ActorInstance | id、trackId、entityId、groupId、shotId、visibilityIntervals、motionRef、rootRef | 同组同时出场也使用独立骨架实例，不能共享当前姿态状态 |
| ShotReconstruction | shotId、coordinateConvention、scaleAssumptions、cameraRef、instanceRefs、qualityRef、inputManifestHash | 每个镜头可独立求解，不跨不同电影强拼一套世界坐标 |
| CameraSample | ptsUs、fx/fy/cx/cy、imageSize、position、quaternion、evidence | 时间化内外参；静态镜头是常量轨迹特例 |
| Pose/RootSample | ptsUs、rootTransform、localJointTransforms、visibility、contacts、provenance | 根运动只应用一次；关节姿态与世界落点坐标明确 |
| EditRecord | id、target、operation、value、baseRevision、author、createdAt、supersedes | 人工编辑独立于模型观测，可撤回与重放 |
| Artifact | id、type、hash、fileRef、inputManifest、algorithmManifest、quality、status | 产物不可变；“当前版本”通过引用切换 |
| PipelineRun/Job | runId、jobId、dependencies及策略、inputHash、scope、attempt、state、outputRefs | 必需依赖成功、可降级依赖满足显式策略后启动；重试不重复发布、不覆盖人工修改 |
| ReviewIssue/ReviewSnapshot | target、interval、reason、resolution、artifactManifestHash | 用户接受近似不等于算法求解成功；审查绑定具体产物 |

建议把现有 `source_people` 迁移为可兼容人物/动物的 `source_entities`，或先通过兼容访问层暴露统一语义。迁移方案选择后才确定表名和 schema 版本；当前代码 schema 为 v6，不在文档中假称迁移已经完成。

### 5.3 时间与坐标约定

- 项目播放时间使用整数微秒 `ptsUs`，以原片首个有效呈现时间为零点；保留原始 PTS 偏移与 timebase。
- 镜头与可见区间统一使用半开区间 `[startUs, endUs)`。现有闭区间 endFrame 在边界适配层显式转换。
- VFR 的逐帧前进按实际呈现帧列表查找。代理若转成固定帧率，必须记录到源时间的映射，不直接把代理帧号当源帧号。
- 世界单位为米、Y 向上、右手坐标系；相机 CV 坐标到 Three.js 坐标的转换只在一个边界函数中完成。
- 记录旋转、缩放、裁剪、letterbox 的完整变换；关键点、框和相机内参统一回到归一化后的原片画面。
- 动作局部姿态、根世界变换、相机世界变换分别存储。不得每帧把最低脚踝强制归零，从而抹掉跳跃或台阶高度。

## 6. 自动任务编排与失败处理

### 6.1 依赖图

```text
media_probe → source_pts ───────────┐
           → preview + time_map ──┼→ cuts
                                  │    ├→ human_observations → human_tracks → human_identity
                                  │    ├→ animal_observations → animal_tracks → animal_identity
                                  │    └→ background_observations → camera_initial
                                  └──────────────┬──────────────────────────────────────────
                                                 ↓
                             provisional_groups + proxy_configs
                                                 ↓
                       per-shot camera / root / pose / contact refinement
                                                 ↓
                        full_timeline_assembly + quality_report
                                                 ↓
                           draft_ready 或 draft_ready_with_issues
                                                 ↓
                         edits → affected_jobs → new_artifact_manifest
                                                 ↓
                                 review_snapshot / exports
```

图表示数据依赖，不强制并行执行所有模型。共享解码可减少重复读片；模型是否同时运行由内存、显存和设备预算决定。切镜与观测任务可以在后续优化为增量处理，但首轮先验证确定性。

每条依赖边必须声明 `required` 或 `degradable`，以及允许的降级产物类型。媒体解码、有效时间轴和产物完整性属于必需条件；部分姿态、身份或相机分支可按能力策略降级。可降级分支失败后，调度器生成显式的 missing/unsupported/placeholder 产物，记录失败 jobId、影响区间和原因，其原任务仍保持 failed。汇合节点仅在全部依赖已有成功产物或允许的降级产物时放行，不能因为可选分支失败无限等待，也不能忽略必需依赖的错误。

降级策略随 pipelineVersion 固定，输入哈希包含依赖结果与降级产物引用。自动任务执行不弹出逐镜确认；最终初稿标记 ready_with_issues，后续恢复真实求解后再发布新版本。

### 6.2 分离三个状态维度

| 维度 | 建议状态 | 含义 |
| --- | --- | --- |
| Job 执行 | queued / running / succeeded / failed / cancelled / superseded | 技术执行情况；succeeded 不代表内容全部达标 |
| 初稿可用性 | not_ready / building / ready / ready_with_issues / blocked | 是否具有完整可播放时间轴及可用产物 |
| 审查 | unreviewed / in_review / accepted / accepted_with_exceptions / stale | 用户对具体版本的审查结果 |

逐镜、逐实例质量另用 `solved / estimated / interpolated / placeholder / missing / unsupported`，附证据和原因。这些状态可以在同一个成功执行的任务产物中并存。

| 情况 | 对后续流程的处理 | 用户看到的结果 |
| --- | --- | --- |
| 身份不确定、遮挡、短时关键点缺失 | 保留候选或有界插值，继续组装全片 | 可播放初稿，标注待核对区间 |
| 一类动物姿态暂不支持 | 保留检测/身份；用显式占位或粗略根轨迹表达 | 显示 unsupported，不计为动作成功 |
| 可选推理分支运行失败 | 记录失败；若已有媒体与时间轴可组装降级初稿，保留问题 | ready_with_issues，同时明确失败分支 |
| 原片无法解码、PTS 不可建立、关键产物损坏 | 阻止依赖该产物的任务，不凭空制造结果 | blocked 或 failed，显示可操作的原因 |
| 磁盘不足、OOM、worker 崩溃 | 终止相关任务并保留诊断，释放资源；按策略重试 | 不覆盖上一有效初稿 |

全片可播放是时间覆盖承诺，不是每帧都已高质量求解。以大量占位拼成的视频只能称为带问题初稿，不能通过最终质量验收。

### 6.3 幂等、取消和发布

1. 在依赖产物提交后计算下游 `inputHash`，内容包括媒体哈希、相关区间、模型/算法/配置版本、人工编辑版本。不要把整个链条锁在上传时同一个即将过期的全局 revision 上。
2. 相同输入的成功产物允许复用；失败任务创建新 attempt。按 `project + kind + subject/scope + inputHash` 去重。
3. 人物重跑只替换人物候选；动物重跑只替换动物候选。检测类型、物种、镜头区间都进入替换范围校验。
4. 人工修正保存在覆盖层；模型重跑生成候选差异。无法自动对应旧轨迹的编辑标记为待重定位，不直接丢弃。
5. 产物先写临时目录，完成校验后原子发布，再在数据库事务中切换引用。中断时旧版本仍可用。
6. 取消信号传播到子进程与待运行节点；取消后的迟到结果不得发布。服务重启回收失效租约，按可复用检查点恢复。
7. 进度来自实际阶段/工作量；总进度不能仅用成功镜头数掩盖失败镜头。界面同时显示已完成、失败、待处理和质量问题数。

## 7. 检测、身份与动物技术路线

### 7.1 切镜与观测

- 保留现有硬切算法作为基线，比较快切、闪白、快速摇移、重复片段、淡入淡出与叠化的效果。
- 硬切使用单一边界；转场可使用 `[startUs, endUs)` 区间和类型。尚不支持的转场进入问题清单，不伪造硬切高置信结果。
- 对很短镜头至少采到代表帧和边界附近帧；不能仅按全片固定步长导致整镜没有观测。
- 跟踪匹配综合位置、运动、外观与类型，处理遮挡与重现；同框交换位置必须专门验证身份是否串换。
- 同时检测人和动物时进行跨检测器重复框核对；不能让同一只动物既计为人物又计为动物，也不能简单按重叠删除骑马画面中的人。
- 帧流、颜色空间、输入尺寸和letterbox映射由适配器测试覆盖。检测概率不得重复施加激活函数。

### 7.2 跨镜素材身份

建议按多帧代表图提取外观特征，融合服装/纹理、体型、局部特征与时间关系；人物面部线索只在有效可见时作为补充。动物使用适配物种的个体特征；“同品种”不是相同身份的证据。

聚类时需要：同框不同个体排斥、明确物种不相容约束、人工锁定、相似但不确定的候选边、可解释代表帧。不要用单个末帧颜色决定整个轨迹的身份。已知人数只能作为用户提示，不应强制把所有出场塞进指定数量并隐藏冲突。

自动合并阈值应优先控制错误合并，同时报告过度拆分率。每次分组重算要保留稳定 ID 对应关系和候选变化记录，避免刷新后角色名称、颜色和用户绑定全部漂移。

### 7.3 动物能力矩阵

“可检测”“可区分个体”“可估二维姿态”“可还原三维动作”分别登记，不能以第一项通过代表全部支持。

| 骨架家族 | 建议开发顺序 | 必须覆盖的代理和动作 | 发布约束 |
| --- | --- | --- | --- |
| 人形 humanoid | 沿用并完善 | CL0–CL2，走跑、转身、部分可见姿态、跳跃与接触 | 与当前人形测试兼容，并补真实素材 |
| 四足 quadruped | 首批动物重点，建议猫/狗/马作为基准 | 头/躯干、前后肢、足端，必要的脊柱/尾部；走跑、转向、站坐、跳跃 | 每个声明支持物种都要有独立测试样本 |
| 鸟类 avian | 独立工作包 | 双足、翅膀、身体朝向；地面移动与飞行分开评估 | 四足通过不能替代鸟类通过 |
| 其他结构 | 按用户素材扩展 | 单独定义关节、运动与接触语义 | 未支持类别保留身份与问题，不冒充已还原 |

同骨架家族内可按尺寸与比例重定向；跨家族分组不能直接套用同一姿态。首轮 UI 对不兼容选择给出明确原因，并保留原有有效绑定。若后续支持跨类叙事组，需要把叙事组与其视觉代理配置再分层。

MMPose 官方模型库提供 AP-10K、AnimalPose 等二维动物关键点方案，可作为候选评估入口；这不等于已经解决跨镜个体身份、三维深度、动物骨架重定向或接触。是否接入须用本项目样本验证，并记录所选权重与关节定义。[官方 Animal 2D Keypoint 文档](https://mmpose.readthedocs.io/en/latest/model_zoo/animal_2d_keypoint.html)

### 7.4 CL 外观与统一骨架

| 等级 | 人物表达 | 动物表达建议 | 不变量 |
| --- | --- | --- | --- |
| CL0 | 头、整体身体、重心与朝向 | 可辨认的身体主轴、头部和整体轮廓 | 保留相同根轨迹与时间 |
| CL1 | 整段四肢、基本姿态 | 四肢或翅膀等主要运动部件 | 使用同家族规范骨架 |
| CL2 | 分段肢体、关节与足端等 | 分段肢体、足/翼端、必要脊柱与尾部 | 表达关键接触，支持细部审查 |

同一骨架家族的三档共享规范姿态和重定向结果；切档只切换可见几何。CL0 不显示足端时，仍可打开骨架/接触辅助显示进行检查。动物部件数按家族定义，不套用人形部件数量。

## 8. 三维还原、播放与导出

### 8.1 逐镜求解，不强拼跨电影空间

每个镜头拥有自己的舞台实例、相机轨迹与尺度假设。全片共享代理资产与舞台预设，但不同来源镜头可以重置空间布局。跨切镜保持叙事身份、代理配置与剪辑时间连续，不默认保持世界位置连续。

求解建议分为：镜头运动初值 → 屏幕构图与根轨迹初值 → 局部动作 → 相机/根运动/接触联合细化。应同时考虑二维关节与框投影、骨长、时序平滑、可见性和接触约束。平滑不能跨切点，也不能把打击、落地等真实快速动作抹掉。

相机不能只用每镜一个固定距离替代：静态、推拉、摇移、跟随、变焦需要时序样本。内参完整使用 fx/fy/cx/cy 与画幅，支持竖屏和非居中主点；观察相机与原片求解相机分离，自由观察不会保存成原片机位。

证据不足时使用明确标注的可编辑初值。单目相机运动与角色运动可能存在多种解释，应优先满足可见构图并保留尺度假设；不能把近似世界轨迹宣传为真实拍摄参数。

### 8.2 动作、走位与接触

- 部分关键点可见时求解可观测部分；缺腿近景不应导致上半身全部丢弃。
- 记录每个关节的观测/估计/插值来源。短缺口建议初始最大插值长度 200 ms，在 P0 按动作类型校准；长缺口不能无限取最近有效姿态或直接跨越插值。
- 根位移、根朝向和局部关节动画分别求解，保留转身、背身、横移、跳跃；不强制所有角色面朝相机。
- 足端接触、落地、坐姿支撑、击打/牵引等分别建模；不具备证据的接触进入问题清单。
- 默认舞台允许不可见或简化接触体。骑乘、人抱动物等跨主体交互同时约束双方，不能分别漂移。
- 将缺失帧、缺失肢体和未求解区间输出到质量报告，而不是先过滤掉再报告优秀误差。

### 8.3 统一时间采样器

```ts
// 时间与产物固定时，结果应可重复；seek、播放、导出共用。
sampleProject({ ptsUs, artifactManifestHash }): {
  shotId: string;
  camera: CameraState;
  instances: Array<{
    instanceId: string;
    groupId: string;
    visible: boolean;
    rigAssetRef: string;
    rootTransform: Transform;
    localPose: JointPose;
    quality: QualityState;
  }>;
  issues: string[];
}
```

采样器负责镜头选择、区间裁切、动作插值、相机采样、可见性与质量状态；界面和离线渲染只消费它的结果。界面播放根据原片实际媒体时间驱动，不累计渲染帧 delta 代替源时间。缓冲时保持两侧对齐，逐帧定位以源呈现帧为准。

Three.js 的 AnimationMixer 提供时间设置能力，可作为骨骼执行层；项目仍需自行实现镜头时间、出场区间和缺失策略。实现时控制 timeScale、局部 clip 起点与重复 seek，不能让动画混合器成为另一套项目时钟。[官方 AnimationMixer 文档](https://threejs.org/docs/pages/AnimationMixer.html)

### 8.4 代理资产与实例

统一入口建议为 `createProxyAsset({rigFamily, rigVersion, proxyLevel, dimensions, color})`。预览和导出使用相同几何/骨架构造逻辑。每组可共享几何与材质资源，但同框多个 ActorInstance 必须有独立骨骼和动画状态。

相机视图按原片比例显示；叠加对照使用相同有效画面区域，不能把 16:9 画布拉伸成竖屏。颜色与名称在身份卡、组列表、时间轴、三维和交付清单中保持一致。

### 8.5 视频与资产导出

建议交付目录：

```text
exports/<exportId>/
  preview.mp4
  manifest.json
  quality.json
  issues.json
  shots.json
  identities.json
  cast.json
  cameras.json
  stage.json
  characters/<groupId>.glb
  motions/<instanceId>.json
  roots/<instanceId>.json
```

- MP4 使用固定输出采样时刻调用同一 `sampleProject`，离线渲染必须等待该帧完成后再编码，不依赖实时屏幕录制帧率。
- VFR 源视频可按明确的输出帧率重新采样，但保留源 PTS 映射。音频按原片时间对齐，不能拉伸视频来掩盖偏移。
- glTF 导出可携带动画 clips，但项目级镜头、组映射、出场时段和质量状态仍需 manifest/JSON 表达；GLB 存在不代表整片语义已完整。[官方 GLTFExporter 文档](https://threejs.org/docs/pages/GLTFExporter.html)
- FFmpeg 的帧率模式可能保留、丢弃或复制帧；源/代理/输出三个时间域都必须实测映射，不能仅比较视频时长。[官方 fps_mode 说明](https://ffmpeg.org/ffmpeg.html#Advanced-options)
- 初稿允许带未解决问题导出，manifest 明确 `reviewState`、覆盖率与缺失范围。“已审查”导出绑定用户审查快照，不要求用户必须逐步审批每个计算任务。
- 资产包可重建相同三维结果：包含坐标约定、单位、模型与算法版本、舞台配置、CL/颜色、音频引用策略及完整时间表。

## 9. 人工修正与局部重算

### 9.1 修改影响矩阵

| 修改 | 必须更新 | 可复用 | 审查失效范围 |
| --- | --- | --- | --- |
| 组名、颜色、CL | 显示资产、预览与导出版本 | 切镜、观测、身份、姿态与相机 | 相关视觉审查/导出；不重新检测 |
| 合并/拆分素材身份 | 身份成员、默认组建议、问题清单 | 原始观测、轨迹 | 相关身份与受影响叙事绑定 |
| 叙事组成员变化，骨架比例一致 | 实例绑定、外观、导出清单 | 局部运动与相机通常可复用 | 相关组与同框关系 |
| 身高、尺寸、骨架家族 | 重定向、尺度相关根运动/接触；必要时相机细化 | 原片、切镜、二维观测 | 相关镜头重建 |
| 关键姿态、朝向、根位置 | 区间动作、接触与受影响相机投影 | 无关镜头和身份 | 相关区间；边界需重新检查 |
| 相机关键帧 | 相机与依赖其尺度/投影的动作细化 | 无关镜头及二维观测 | 当前镜头及依赖结果 |
| 切点 | 受影响镜头的轨迹切分、身份建议、重建和时间表 | 源帧级检测与特征可按新范围复用 | 新旧边界相关区间 |
| 删除误检或补标 | 对应轨迹、身份、实例、质量统计 | 无关轨迹 | 对应镜头与统计 |
| 更换模型 | 依赖该模型的自动候选 | 人工编辑记录、原片、无关分支 | 受影响算法产物，不自动重写用户决定 |

颜色/CL 改变虽不重算算法，也要生成新显示版本。局部重算后必须刷新质量报告；否则不能只换画面而沿用旧“已通过”状态。

### 9.2 并发编辑原则

修改携带 `baseRevision`，过期写入返回 409 与当前版本摘要。长任务使用产物级输入快照；运行中出现上游编辑时，旧结果可保留在历史，但不能自动成为当前版本。导出锁定一个 manifest，不读取过程中不断变化的当前表。

人工锁定的身份、分组或关键帧遇到新算法结果，应显示差异并允许选择；默认保留人工决定。撤销操作产生新编辑版本，不删除原始观测和历史记录。

1. 为 B1–B3 建立失败回归，再实现按 subject 重跑、动物拆分与接口类型校验。
2. 给角色组加入 `proxyLevel/rigFamily/rigVersion`，自动配色；存储、API、UI、导出共用配置。
3. 建立 SourceEntity 与 CastingBinding 的来源/锁定语义；人物和动物分区展示暂定身份数。

## 11. 真值集与评测协议

### 11.1 样本组织

建议第一轮准备至少 20 段、每段 10–60 秒的真实短片，加上 120 秒容量边界片和合成媒体 fixture；数量是启动建议，不代表统计充分。每个声明支持的动物物种和关键动作必须有覆盖。

| 维度 | 必须包含的样本 |
| --- | --- |
| 身份 | 同一人跨镜、换装/光照、不同人同服装、同一演员不同素材角色、重复片段 |
| 叙事 | 两个素材身份合为一组、同一身份按出场分组、同组同框、忽略路人 |
| 动物 | 同一动物跨镜、同品种多只、不同物种、人和动物同时出现、遮挡重现 |
| 画面 | 远景、近景缺腿、背身、多人交叉、空镜、字幕/水印、运动模糊 |
| 动作 | 走跑、转身、跳跃落地、坐/躺、快速打击、动物步态、人动物互动 |
| 相机 | 静态、推拉、摇移、跟随、变焦、运动背景、缺少背景纹理 |
| 时间 | 快切、闪白、叠化/淡入淡出、重复/倒放片段、变速、VFR、非零初始 PTS |
| 格式 | 横屏、竖屏、旋转元数据、无音轨、音频偏移、范围内/超界/损坏文件 |

开发集用于调参，保留测试集用于最终验收；同源电影片段或近重复片段不跨两组泄漏。记录媒体哈希、来源、时长、画幅、标签版本和允许保留的范围。没有真实素材时可完成工程测试，但识别与还原效果标为未验收。

### 11.2 真值标注

真值至少包含：镜头边界与转场区间、可见主体框/掩码、subject/species、镜内轨迹、跨镜素材身份、人工定义的叙事组、可见关节、朝向、足端/交互接触、关键动作区间，以及可评价的相机地标。

真正无法从视频确定的身份或三维量标为 ambiguous，不能让标注者猜出“真值”。这类区间仍计入整体可处理范围报告，另外检查系统是否正确暴露不确定性。相机三维精度只在有测量或可信人工参考的子集中评价。

### 11.3 指标口径

- **切镜**：以新镜头首个源呈现帧为真值；预测/真值一对一最小距离匹配，允许 ±2 源帧。报告 recall、precision、误切/漏切列表；转场另计，不混入硬切指标。
- **主体出场**：主指标先限定持续 ≥0.3 秒、在长边归一化 1280 的画面中人物框高或动物框长边 ≥80 px，且可辨识主体。短暂/远小/严重遮挡另外分层，不能从全片报告消失。轨迹匹配要求覆盖 ≥50% 可见时间、重叠标注帧框 IoU 中位数 ≥0.3，一对一匹配。
- **身份**：人工真值区分人物身份和动物个体；报告成对身份 precision/recall/F1、错误合并/拆分数、镜内 ID 串换、每片唯一数量绝对误差与完全正确片段比例。逐类结果与总体宏平均都保留。
- **计数**：先报告纯自动身份数，再报告人工修正后的身份数；叙事组数单独统计。人工填写人数、人工合组后的结果不能冒充自动识别准确率。
- **覆盖**：分母是所选主体的真值可见时间之和（同时两人可见一秒计两主体秒）；分别报告有效求解、有限插值、占位、缺失、未支持比例。全片时间覆盖与动作有效覆盖是两个指标。
- **误差**：几何误差在已求解且可评价区间计算，同时报告覆盖率；不得只剔除困难帧后报低误差。按主体与镜头给中位数、P95，列出未评价原因。
- **构图**：评价投影主体中心、相对画面尺寸、可见关节与前后遮挡次序；默认舞台与原背景不做整幅像素相似度比较。
- **动作**：骨长、二维关节重投影、动作事件时间与接触检查结合。长缺口的自动补全不等于真实观测；人工评分与自动指标分别报告。
- **运镜**：有地标时计算重投影误差；其他镜头记录运动方向、构图轨迹、变焦趋势和人工连续回放结论，不捏造真实三维外参精度。
- **性能**：记录实际 CPU/GPU、内存/显存、provider、模型哈希、输入特征、冷/热启动、总时间、各阶段时间和峰值资源；公布样本数与失败样本。

身份成对指标必须同时报告漏检轨迹数及检测召回，避免只对检出的少数主体计算漂亮的身份分数。动物每个声明支持类别分别放行，不能让人形或常见物种的平均分掩盖其他类别完全失败。

## 12. 验收标准

### 12.1 门槛使用规则

下表的 **H** 是确定性的功能硬门槛；**Q** 是建议的质量数值初值，需要 P0 在冻结数据集和支持范围时确定；**P** 是建议的性能预算。Q/P 未冻结或未实测时必须标为“未验收”，不能写“已通过”。如基线发现目标不可达，应保留原目标、差距和调整理由，不能为了通过结果悄悄降低门槛。

“自动初稿验收”不允许人工改身份/动作后再计自动分数；“修正后交付验收”另存编辑次数、耗时和最终结果。用户接受例外不自动将对应 Q 项判为通过。

| 编号 | 类型 | 验收对象 | 验收标准 | 必须保留的证据 |
| --- | --- | --- | --- | --- |
| A01 | H | 导入与原片 | 冻结范围内 fixture 全部导入/seek 成功；原片哈希不变；坏文件明确失败；横竖屏/旋转正确 | 媒体报告、源/代理时间映射、哈希、失败日志 |
| A02 | H | 自动全流程 | 新建上传后无需点击检测/确认角色即可生成全时长初稿；人物/动物分支自动执行；空镜可播放 | 浏览器录像或操作记录、run 依赖图、产物 manifest |
| A03 | Q | 切镜 | 硬切 recall ≥95%、precision ≥90%；±2 源帧匹配；所有误切漏切可修正，修正后时间线无缝 | 真值/预测匹配表、转场分层结果 |
| A04 | Q | 主体发现与跟踪 | 人物与每个支持动物类别的主范围出场 recall ≥95%；precision ≥90%；所有 ID 串换逐例列出 | 轨迹匹配、漏检/误检、同框交叉回放 |
| A05 | Q/H | 跨镜唯一身份 | 自动成对身份 precision ≥98%、recall ≥90%；每片唯一数量完全正确比例 ≥90%，人/动物分别报；基准中同一只动物跨三镜算一个身份 | 原始自动簇、身份真值、误合并/拆分、计数误差 |
| A06 | H | 叙事分组 | 不同素材个体可同组；原身份不被破坏；出场级覆盖、移出/拆组/撤销可用；同组同框保持独立实例并提示 | API/UI 回归、重启回读、实例清单 |
| A07 | H | CL、颜色、骨架 | 每组独立 CL；切档不改时间/根轨迹；默认颜色不重复且有名称区分；重启、预览、导出一致；不兼容骨架无静默套用 | 配置快照、三档截图、GLB 回读与实例对比 |
| A08 | H | 动物完整链路 | 每个声明支持物种完成检测→身份→分组→适配代理→动作→播放→导出；同品种多只不按类别合一；不支持项明确标记 | 按物种能力矩阵、端到端片、动物动画回读 |
| A09 | Q | 有效动作覆盖 | 人物与每个支持动物类别有效求解覆盖各 ≥90% 主范围主体可见时间；插值、占位、missing 单列；关键动作不得靠长占位通过 | 按主体秒统计的覆盖表、问题区间、全片回放 |
| A10 | Q | 构图与动作投影 | 长边1280归一化：主体中心误差中位数 ≤画面对角线2%；框尺度相对误差中位数 ≤10%；可见关节中位误差 ≤10px、P95 ≤30px | 投影叠加、逐镜/逐主体误差、覆盖分母 |
| A11 | Q | 骨长、根运动、接触 | 规范骨架骨长相对偏差 ≤0.1%；标注稳定接触期足端非预期水平滑动建议 ≤体高2%；关键跳跃/落地/转身时间误差 ≤2输出帧；无未解释严重穿插 | 骨长/接触报告、根轨迹、关键区间人工回放 |
| A12 | Q/H | 相机与默认舞台 | 有可靠地标子集重投影中位误差 ≤8px（长边1280）；其余明确估计；静态/推拉/摇移/跟随/变焦样例方向正确；舞台不阻断生成 | 相机轨迹、地标、构图曲线、人工结论 |
| A13 | H | 播放与剪辑时间 | 随机 seek/逐帧/重复播放采样一致；无跨切点插值；主体只在有效区间出现；实际显示同步差 ≤1源呈现帧，VFR按帧表 | 源/三维时间日志、首中末与每个切点检查 |
| A14 | H | 统一修正与重算 | 改颜色/CL不重检；改一镜相机不重算无关镜头；任务中编辑不会被迟到结果覆盖；撤回与重启保留人工决定 | 任务执行清单、输入哈希、前后版本 diff |
| A15 | H/Q | 视频与资产 | H：MP4时长差 ≤1输出帧，GLB/JSON回读后组数、CL、颜色、实例时间、骨架和关键姿态一致；Q：相对源片的新增音画偏差建议 ≤40ms，P0冻结预算 | 编码信息、首中末音画对照、回读脚本、manifest |
| A16 | H | 故障与恢复 | 人/动物单独重跑互不覆盖；取消/崩溃/重启/缺模型/OOM/磁盘不足不损坏原片与上一有效版本；409不吞用户修改 | 故障注入与临时数据库记录、产物校验 |
| A17 | P | 性能与资源 | 基准机上720p、最多4个同时可见支持主体时，建议预览P95帧耗时≤33ms、seek P95≤500ms（资源已载入）；30秒片初稿总时长建议≤片长10倍 | 硬件/模型/provider、冷/热数据、分阶段耗时与峰值 |
| A18 | H | 诚实状态与可追溯性 | 执行成功不等于质量通过；占位/缺失/未支持均可定位；报告有分母、输入与算法版本；所有已审查导出绑定快照 | 质量报告、问题清单、审查与导出版本 |

颜色超过易区分调色板容量时，继续用名称、编号和轮廓辅助区分，不能仅依赖颜色。A07 的“不同颜色”应按冻结的最大角色数验证，不把无限数量的色差承诺写死。

A10/A12 的像素指标统一按长边 1280 缩放（16:9 对应 1280×720），原始像素误差同时保留。A11 的接触应区分支撑、滑动、飞行与被拖拽等语义，不能把真实滑动动作误判为错误。

A15 的音画基准是源片已有的同步关系：在首、中、末选择可定位的音频事件与对应源时间画面，比较输出新增的时间偏移，并保留解码时间戳与抽样记录。无音轨素材该子项记 N/A，既不失败也不计入音画同步通过样本；视频时长和资产回读仍须验收。

### 13.2 六条端到端验收剧本

1. **人物混剪**：上传至少两段来源、包含重复人物的视频 → 不点任何分析按钮 → 得到全片初稿 → 合并叙事组 → 改CL/颜色 → 仅更新受影响产物 → 导出并回读。
2. **动物混剪**：同一只动物跨三镜、另一只同品种动物同时或分别出现 → 独立身份卡 → 人工合为叙事组 → 适配动物代理和动作 → 整片播放/导出一致。
3. **人动物混合**：人、狗、马与重叠互动 → 分区计数 → 独立重跑动物 → 人物身份和人工决定不变 → 验证双方动作与接触。
4. **不确定素材**：背影、遮挡、运动模糊、近景缺腿 → 初稿不等待核对 → 问题定位正确 → 修改一处身份和一段姿态 → 其余镜头不重算。
5. **时间与画幅**：竖屏VFR、快切、无音频及音频偏移样本 → 首中末/切点/随机seek对照 → 检查渲染和音画同步。
6. **恢复与升级**：v6副本迁移 → 运行中取消/重启 → 恢复可复用阶段 → 保留旧初稿和人工修正 → 过期写入被拒绝 → 正常导出。

### 13.3 执行方式与证据

现有 `npm run check`、`npm run build` 继续作为工程检查入口。新增测试名称与脚本路径在实现时确定，不能把本文的拟议脚本写成已经可运行。性能与识别评测单独运行，不能由合成单元测试代替。

自动测试使用一次性目录和数据库，不访问真实项目。现有 [acceptance-mixed-cut.mjs](../scripts/acceptance-mixed-cut.mjs) 会向服务创建并保留项目；后续先改成可配置独立数据根/临时服务，再用于常规回归，避免默认往用户工作库里写验收数据。

每次正式验收包建议包含：数据集 manifest、模型/运行环境、测试输出、自动指标 JSON、逐镜问题 CSV/JSON、关键截图、完整回放、导出产物哈希及回读报告。自动运行与人工修正后的结果分别存目录。

## 14. 迁移、性能与交付要求

### 14.1 迁移与兼容

1. 从当前 v6 建立最小迁移测试，备份数据库与必要产物索引；说明数据库备份不包含原视频文件。
2. 旧人物映射到 `subjectType=person` 的 SourceEntity，保留原 ID 或可追溯映射。旧动物轨迹迁移为未核对候选，不凭类别批量合并个体。
3. 旧角色组的 CL 缺省值建议 CL1，但标记为迁移默认值，不能声称恢复了用户此前未保存的预览选择。
4. 旧 `cast_approval` 作为历史审查保留；不把它升级成 V2 动作、相机或动物已通过。V2 初稿不受旧人工关卡阻断。
5. 新重建产物放独立版本目录；旧 JSON/GLB 不原地覆盖。读取适配层允许查看旧项目，旧 JWM 与演练状态不混入新流程。
6. 迁移失败保持备份与可诊断状态，不启动写入新 schema 的任务。回退使用匹配代码版本和备份副本验证，不对用户库尝试降级覆盖。

### 14.2 性能与资源

- 首轮先记录本机实际硬件与 provider，不假设 GPU 一定可用，也不默默切换远程服务。
- 尽量复用解码、代表帧、特征和二维观测；重跑颜色/CL不触发模型推理。
- 大数组按镜头/区间分块，避免把整段视频的所有张量和动画都放进 React state 或单个 JSON 响应。
- 同时可见实例数决定渲染压力；长列表与时间轴按需加载。共享几何不等于共享实例骨骼状态。
- 并发上限依据模型内存和实际设备；OOM需要明确失败或按预先声明策略缩小批次，不能无记录降分辨率改变验收条件。
- 记录缓存命中、峰值磁盘和临时空间需求。用户请求取消后释放资源，历史有效产物仍可回放。

### 14.3 完成交付清单

实现交付应包括代码、数据迁移、受影响测试、真实样本评测、浏览器验证、使用说明、模型/能力矩阵、质量报告规范和未解决问题。公开部署、凭证变更、云分析和远程数据存储属于另行明确目标的操作，不在这份开发文档中自动授权。
