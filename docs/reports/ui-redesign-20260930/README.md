# NexArtMS 前端改版实施与验收记录

日期：2026-09-30（Asia/Shanghai）

范围：项目首页、拉片、人物、三维还原及其设置／任务／修正入口。

## 结论

本轮 UI 交付已完成。默认界面以画面和结果为主，镜头定位收敛为唯一镜头条；镜头表展开时替换镜头条，编辑与高级工具由用户主动打开。正式构建通过，核心简约结构、草稿保护、失败恢复及跨视图时间保持已在真实组件中验证。

本记录区分“通过”“局部验证”“未测”。UI 改版没有增加人物识别、动作生成或相机求解能力；真实项目仍缺人物检测权重，真实三维动作最终效果及付费 Provider 没有验收。A01–A14 不全部记为通过。

设计依据：[前端改版方案与验收标准 v2](../../../plans/ui-redesign-plan-20260930.md)。方案文件保留原提案目标；本记录描述实施结果与实际证据。

## 已实施的界面与交互

| 部分 | 当前行为 |
|---|---|
| 项目首页 | 紧凑项目列表与一个“导入素材”主入口；已有结果可直接打开。 |
| 项目工作页 | 统一项目顶栏与拉片／人物／三维还原三个视图；不重复进入设置流程。 |

| 人物 | 默认人物目录；选中人物将同一镜头条限定到相关镜头，清除后恢复全部镜头；人物修正与出场高级操作主动打开。 |
| 三维还原 | 原片／三维对照；只有一个视角选择器；角色与相机修正面板默认关闭。缺动作、占位、缺相机等状态如实表达。 |

草稿保护覆盖拉片、人物名称、角色／相机等高级修正和项目设置。切换镜头、视图或收起面板保留输入；返回项目列表前明确选择继续编辑或丢弃。存在人物／高级工具草稿时，更新拉片、调整切点、采用候选版本等跨版本操作被阻止，并说明先保存或撤回，避免下游版本变化静默覆盖输入。

## 复现方法

运行环境沿用项目README；本次在macOS本机完成。以下命令均从 `app` 目录执行。

### 正式界面

```sh
npm run build
npm run serve
```

浏览器打开 `http://127.0.0.1:8199/`。只读观察真实项目时不要点击“更新还原”、分析重试、保存设置或任何业务写入操作。

### 隔离UI夹具

```sh
node scripts/studio-ui-fixture.mjs
```

浏览器打开 `http://127.0.0.1:8208/?project=fixture`。顶部注明“隔离UI夹具 · 合成画面／内存数据”；可切换200镜、空项目、非零起点和项目列表。接口写入只改变夹具内存，停止该进程后状态和临时媒体清理。

复查顺序：默认镜头条／展开表互斥 → 主动修正 → 草稿切换保留 → 人物范围清除 → 原生弹窗焦点与Esc → 冲突／提交失败恢复 → 零／非零PTS定位。浏览器交互与截图需实际操作组件，不以静态示意图替代。

### 核心前端与同步回归

```sh
node --import tsx --test scripts/studio-playback-clock.test.ts scripts/studio-stage.test.ts scripts/studio-identity-ui.test.ts scripts/studio-model-settings-ui.test.ts scripts/studio-shot-analysis-ui.test.ts
```

此命令复现核心子集。完整91项聚焦批次的命令为：

```sh
node --import tsx --test scripts/studio-shot-analysis*.test.mjs scripts/studio-playback-clock.test.ts scripts/studio-stage.test.ts scripts/studio-identity.test.mjs scripts/studio-model-settings*.test.mjs
```

全量检查用 `npm run check`，其本机已知删除测试失败须按上文单列。
