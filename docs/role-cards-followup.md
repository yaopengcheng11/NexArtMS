# 角色卡片修正（2026-09-25）

## 交互

- 全片角色默认只显示素材角色卡片；点击某个角色后，才显示其去重镜头列表。
- 镜头中的分段轨迹放在进一步展开的修正入口中。无法确定归属的出场只显示一个“待核对出场”入口，可按镜头检查并归入角色。
- 不同素材角色可以绑定同一代理组，仍保留各自的角色卡片和出场动作。
- “整理角色”支持用户提供已知角色数量。数量保存为当前项目的 `source_people_count`，新项目默认未知，程序没有把所有视频写死为两人。

## 当前项目实测

用户确认该视频有两名角色，已据此为当前项目保存人数提示并重新检测。

- 原先 518 个有效旧片段被显示成 518 张卡片。
- 修正检测解析并重新处理后，有 121 条有效镜内轨迹。
- 主界面显示两张角色卡，代表图分别对应两名素材人物。
- 自动汇总暂时归属 53 条出场，另外 68 条留在待核对入口；没有为凑够人数而强行归属。
- 点击两张卡时分别列出 29、17 个去重镜头。这里的数量是当前自动归属结果，需要人工核对，不能作为完整身份真值。
- 另一验收项目的所有代理绑定在操作前后 SHA-256 一致。

## 一并修复的检测错误

当前 ONNX 模型输出已经是概率，旧代码重复执行 sigmoid，使背景候选无法通过阈值被淘汰。实机首帧的 class 概率范围为 `0–0.9102067`；原始有 10 个 anchor 高于 0.25，重复转换后变成全部 8,400 个高于阈值。

现在直接读取 class 和关键点可见性概率，检测记录标记 `decode-probabilities-v2`。模型及其权重未替换。[Ultralytics 官方输出实现](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/nn/modules/head.py)可核对导出前的 sigmoid。

## 数据与验证

- SQLite v4 增加项目人数提示列，v5 保存角色的代理分组。v3 之后升级不再调用旧身份回填流程，未归属轨迹的 NULL 在重启后保持不变。已有数据库升级前自动备份。
- 出场归入角色时同步该角色的代理组；移回待核对时解除绑定。代理归属变化会清除过期动作引用；即使角色暂时没有出场，也保留其代理组。
- 原始媒体、历史轨迹及已有导出保留；旧自动候选标记为 superseded。已有人工身份决定受保护，旧代理绑定不被自动身份汇总改写。
