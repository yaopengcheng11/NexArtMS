# 代码复核：项目管理、全片人物与代理角色分组

日期：2026-09-25。范围：`studio/`、混剪工作台、动作与交付管线。保留用户已有代码及项目数据；本轮未提交或推送 Git。

## 用户流程与数据含义

1. 检测产生镜内出场轨迹，每条轨迹保留实际匹配的逐帧观测。
2. 按外观线索把轨迹汇总为整片的**素材人物候选**：代表截图、出现镜头、出场片段。
3. 用户标记人物；同一个人被多分时可以合并，不同人被错合时可以拆出出场片段。
4. 用户勾选不同素材人物，分到一个**代理角色组**；每组复用一个名称、颜色、身高及代理资产。
5. 动作仍按各段出场独立生成。每组导出一个 GLB，组内每条有效动作对应一个动画片段；镜头时序与原片帧区间写入 manifest。

例：素材人物 A 出现在 S01/S03，人物 B 出现在 S07。将 A、B 都分到“主角组”后，三段出场共享主角代理外观，动作和镜头时序各自保留。

同镜同时出现的人物不能自动视为同一素材人物。若最终代理组允许分身/镜像，需要用户明确勾选允许同框。

## 实现内容

| 功能 | 行为与入口 |
| --- | --- |
| 项目设置 | 工作台右上角；名称、说明、不建可见场景/请求可见场景；带 revision 校验 |
| 项目删除 | 设置内输入完整项目名确认；删除该项目元数据、素材、预览、动作及导出文件 |
| 删除活动屏障 | 正在上传、生成截图、读取文件或运行/排队任务时返回 409；取消须等到任务真正结束 |
| 删除一致性 | 校验目标目录、拒绝目录链接；先移入受控暂存目录，事务清理数据库，再清理文件；文件清理失败明确报告保留位置 |
| 全片人物卡片 | 显示候选数量、代表截图、去重镜头列表、出场片段与所属代理组；可搜索、批选、标记、合并、拆开、忽略 |
| 自动汇总 | `body-colour-complete-link-v1`：上下身颜色直方图、保守阈值、歧义拒识、同框排斥；自动结果标为待核对 |
| 人工决定保护 | 自动汇总跳过已核对/已分组/已忽略的人物；重新检测拒绝覆盖已有人工核对的自动候选 |
| 迁移 | SQLite v2→v3；迁移前 `VACUUM INTO` 生成一致性备份；保留旧 track ID、binding、项目与产物 |
| 代理资产 | `proxy-segments-v2`，有效三角面蒙皮，14 条刚性骨段；每组一个资产，支持多动画片段 |

旧项目在升级后会先保留原有候选。点击“按外观重新汇总”可处理旧检测结果；既有人工分组不会被覆盖。此操作只增加外观汇总，不会修复旧检测已经丢失的逐帧关联证据。需要新的姿态证据时应重新检测；已有人工标记的数据可保留在旧项目，在新项目重新导入分析。

## Review 确认并修复的问题

| 级别 | 缺陷 | 本轮处理 |
| --- | --- | --- |
| P1 | FFmpeg `data` 异步回调并发复用推理张量，且进程结束可能早于最后推理结束 | 改为逐帧等待的异步迭代，并等待所有回调完成 |
| P1 | 60 fps 以 stride=6 采样，跟踪允许间隔却仅 3 帧，每次采样都断轨 | 允许间隔与实际采样步长一致 |
| P1 | 跟踪仅保留末帧框，再用该框反查历史关键点，移动人物可能串姿态；截图也用错时间 | 保留每次一对一匹配的观测，截图使用同一次观测的帧和框；旧错误缩略图换缓存键 |
| P1 | 再次检测不断追加有效候选，重复计数与同框冲突累积 | 替换未核对自动版本；保留人工轨迹，拒绝覆盖人工分组 |
| P1 | 重试仅把数据库状态改为 queued，不重新调度 | runner 实际重新排队，并隔离取消后重试的旧调度回调 |
| P1 | 改组或改身高后仍导出旧动作，身份/比例与 manifest 不一致 | 失效相关 motion_ref；导出再次验证角色、身高、帧区间；缺失动作明确列出 |
| P1 | 改切点后越界轨迹仍可重新确认；拆分/连接后姿态范围不一致 | 阻止越界确认、动作生成和导出；清除旧相机/动作引用；按轨迹区间处理姿态并复制拆出数据 |
| P1 | 单个手腕等关键点被遮挡时读取 undefined，整段动作任务崩溃 | 检查所需关节和有限坐标，缺失帧跳过并计入报告 |
| P1 | GLB 24 个顶点只有 1 组蒙皮属性；wireframe 导出成 LineSegments | 每顶点完整蒙皮属性，导出实体三角面；回读必须得到 SkinnedMesh |
| P1 | GLB 父四元数原地被改，骨段绑定坐标不成立，回读关节位置偏差大 | 改为明确的骨段代理 rig，直接按源动作的位置、方向和长度驱动 |
| P2 | 手机端原有 CSS 隐藏整个顶栏操作区，新项目设置/返回入口不可用 | 保留窄屏顶栏操作，实测 390px 设置与删除 |
| P2 | 冻结的旧算法版本覆盖新导出版本；新骨架沿用旧 DCC 验证说明 | 实际导出版本固定取当前版本；新 rig 的 DCC 回读明确记为未实测 |

另补充上传前的版本检查、上传提交失败后的文件清理、文件下载流错误处理。

## 验收证据

- `npm run check`：78 项；覆盖新旧数据库、同人跨镜合并/拆分、不同人同组、人工决定保护、动作失效、删除范围和上传并发、任务实际重试、高帧率观测、遮挡、异步帧流。
- 有动作导出回归：两个素材人物 → 同一代理组 → 一个 GLB、两段动画；GLTFLoader 重新载入，检查每个顶点属性数量及每条骨段端点，误差要求 `< 1e-5 m`。
- 独立复核使用两条已有真实 motion 在内存重建并回读：14 个 SkinnedMesh、2 个 clip，首/中/末检查帧最大端点误差 `3.26e-8 m`。这是导出忠实性验证，不代表单目动作还原的真实精度。
- `npm run build`：TypeScript 与 Vite 构建通过；保留已有大资源包体积提示。
- `node scripts/browser-studio-v3.mjs`：9 项通过，独立临时库与临时视频；实测设置、分组、跨镜合并、刷新、390px、删除确认、返回列表、目录清理、无页面脚本异常。
- 证据：`reports/studio-v3-browser.json`、`reports/studio-settings-v3.png`、`reports/studio-people-v3.png`、`reports/studio-people-mobile-v3.png`。

## 尚未完成的产品能力

- 外观汇总是启发式候选，没有真实跨镜身份识别基准；相似服装、换装、光照变化仍需人工核对。不能把候选数量当成已经证明的实际人数。
- 整片三维代理视频渲染尚未实现。现有素材转码任务已改称“生成素材预览”；本轮交付的是分组数据、动作和共享 GLB 资产。
- 可见场景制作、完整相机运动还原、真实混剪动作精度与新代理骨架的 Blender/Maya/Houdini 回读尚未验收。
- 历史导出包保持原样；新代码不会悄悄重写用户的旧交付文件。

因此，本轮管理与分组功能可用，产品仍处于需要人工核对的原型阶段。
